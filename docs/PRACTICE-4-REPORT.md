## Вторая функция

В ветке `feature/second-feature` добавлен поиск по названию задачи.
Поле «Поиск задач» обновляет список сразу при вводе. Поиск не учитывает
регистр, поддерживает кириллицу и фразы, игнорирует пробелы по краям.
Он сочетается с прежними фильтрами: «Все», «Активные», «Выполненные».
Если совпадений нет, отображается «По вашему запросу задач не найдено.».
Пустая строка возвращает все задачи выбранного раздела.

Поиск не меняет задачи и localStorage. Ключи хранения прежние:
`zadachnik.tasks.v1` и `zadachnik.filter.v1`. Добавление, отметка выполнения,
удаление, очистка выполненных, счётчик и восстановление после перезапуска
сохранены. Выбранный поисковый запрос после перезагрузки очищается.

## Рефакторинг с минимальным риском

Выбор видимых задач выделен из длинной функции `render()` в отдельный
файл `task-view.js`, функцию `selectVisibleTasks(tasks, filter, searchText)`.
Она возвращает отфильтрованный массив, не меняя исходные данные.
Нормализация запроса теперь выполняется один раз за вывод списка.
`render()` отвечает за отображение, чистая функция — за поиск и фильтрацию.
Модуль подключён перед `app.js` обычным script, поэтому запуск через
открытие index.html сохранён и сборщик не требуется.

Сначала прошла проверка старых сценариев на исходной версии. Затем один
и тот же расширенный набор проверок прошёл перед рефакторингом и после него:
два теста, ноль ошибок. Проверки исполняют настоящие app.js/task-view.js
в Node.js с моделью DOM и localStorage и вызывают обработчики событий.
Это автоматическая проверка логики; визуальный прогон в браузере в рамках
этой работы не выполнен.

## Учебный конфликт: до и после

От коммита рефакторинга создана ветка `feature/interface-text`.
В обеих ветках по-разному изменён один заголовок в `index.html`:

- `feature/second-feature`: «Задачник с поиском»;
- `feature/interface-text`: «Мой задачник».

При `git merge feature/interface-text` получен настоящий конфликт содержимого.
[Сохранённый diff с маркерами](practice-4/conflict-before.diff) и
[git status с UU index.html](practice-4/conflict-status.txt).

Фрагмент до исправления (с номерами строк):

```text
12 | <<<<<<< HEAD
13 |       <h1>Задачник с поиском</h1>
14 | =======
15 |       <h1>Мой задачник</h1>
16 | >>>>>>> feature/interface-text
```

Файл открыт, маркеры удалены ручной правкой, выбран объединённый вариант:

```html
      <h1>Мой задачник с поиском</h1>
```

Затем выполнены `git add index.html`, проверка синтаксиса, тесты,
`git diff --cached --check` и merge commit. Feature-ветка слита в main
отдельным merge commit с `--no-ff`. Копия diff с маркерами сохранена только
как доказательство конфликта; в исходных файлах маркеров нет.

## Проверки и воспроизведение запуска

Node.js v24.22.1, Windows. Запуск проверок:

```text
node --test tests/app.test.cjs
node --check app.js
node --check task-view.js
git diff --check
git status --short
```

[Фактический журнал запуска проверок после слияния](practice-4/tests.txt).
Проверены прежние операции, повторный запуск с сохранёнными задачами
и фильтром, пустой ввод, буквальное отображение HTML-текста, поиск
по кириллице и фразе, сочетание с фильтрами, пустой запрос, отсутствие
совпадений и неизменность сохранённых задач. Тестовые данные изолированы
в памяти, пользовательские данные не затронуты.

Для ручной демонстрации откройте `index.html` в браузере:

1. Добавьте «Купить молоко» и «Купить хлеб».
2. Отметьте «Купить молоко» выполненной.
3. Введите в поиск «МОЛОКО»: останется выполненная задача «Купить молоко».
4. Выберите «Активные»: появится сообщение об отсутствии совпадений.
5. Выберите «Выполненные»: снова появится «Купить молоко».
6. Очистите поиск и выберите «Все»: обе задачи видны с прежними статусами.
7. Перезагрузите страницу: задачи восстановятся.

Итоговая ветка main и обе учебные ветки опубликованы на GitHub.
После коммита отчёта рабочее дерево чистое, `git diff --check` проходит.
Работа и ручная правка конфликта выполнены с помощью ИИ.
